###  Общее описание

Проект представляет собой комплексную математическую библиотеку на **C++20**, объединяющую архитектурные паттерны ООП и вычислительную линейную алгебру.

Первая часть (Информатика) фокусируется на реализации полиморфной иерархии абстрактного типа данных «Матрица». Строго следуя принципу инверсии зависимостей (SOLID), хранилище данных матриц инкапсулировано через `DynamicArray<T>`, реализованный в предыдущей лабораторной работе.

Вторая часть (Алгебра) использует созданные матрицы для решения систем линейных алгебраических уравнений (СЛАУ) различными численными методами. В проект встроен специальный стенд для профилирования и сравнения алгоритмической сложности (замеры времени выполняются с помощью `std::chrono`).

Проект снабжён **интерактивным консольным UI**, который полностью защищен от некорректного ввода пользователя, а также покрыт обширными модульными тестами **Google Test**. Благодаря `TYPED_TEST`, все алгоритмы автоматически тестируются как на обычных вещественных числах (`double`), так и на комплексных (`Complex<double>`).

###  Подробное описание: Информатика (ЛР-3)

Разработанная архитектура строго соблюдает концепции объектно-ориентированного программирования[cite: 11]. Базовый интерфейс `IMatrix<T>` объявляет чисто виртуальные методы, заставляя каждого наследника реализовать свою логику `Get` и `Set`[cite: 11].

*   **Инкапсуляция абстракции Sequence:** Главный класс `Matrix<T>` физически не привязан к сырым C-массивам[cite: 11]. Его данные скрыты в указателе `Sequence<T>*`. Это паттерн инверсии зависимостей: мы можем легко переключить хранилище с массива (`ArraySequence`) на список (`ListSequence`), не меняя код самой матрицы.
*   **Оптимизация памяти (Triangular / Diagonal / Band):** Матрицы специального вида не тратят память на хранение заведомых нулей[cite: 11]. Например, `TriangularMatrix` использует одномерный `DynamicArray` размером $\frac{N(N+1)}{2}$ и математическую формулу трансляции 2D-индексов $(i, j)$ в 1D-индекс массива, что экономит $\approx 50\%$ оперативной памяти по сравнению с плотной матрицей[cite: 11].
*   **Разреженная матрица (SparseMatrix):** Структура, предназначенная для матриц огромных размеров с экстремально малым количеством полезных данных[cite: 11]. Хранит только ненулевые элементы в виде линейного динамического массива структур `{row, col, value}`. Для обеспечения амортизированной сложности $O(\log K)$ при доступе реализован алгоритм бинарного поиска элементов по отсортированным координатам.
*   **Кастомный тип комплексных чисел (`Complex<T>`):** Для поддержки вычислений с комплексными числами вида $a + bi$ реализован собственный шаблонный класс[cite: 11]. Перегружены все базовые арифметические операторы, а также потоковые `<<` и `>>` для бесшовной интеграции с консольным UI[cite: 4]. Ключевая архитектурная особенность - безопасное сравнение вещественных чисел: с помощью конструкции C++17 `if constexpr (std::is_floating_point_v<T>)` оператор `==` автоматически адаптируется под тип `T` и сравнивает значения через машинный эпсилон (`std::numeric_limits<T>::epsilon()`), что защищает алгоритмы линейной алгебры от фатальных ошибок машинного округления.

###  Подробное описание: Линейная алгебра (ЛР-1)

Вся логика вычислительных методов инкапсулирована в пространстве имен `LinAlg` (файл `SLAE.hpp`).

#### 1. Метод Гаусса (С частичным выбором ведущего элемента)
Классический алгоритм прямого хода (приведение матрицы $A$ к верхнетреугольному виду) с последующей обратной подстановкой.
*   **Проблема нулевого пивота:** Нативный Гаусс завершается фатальной ошибкой (деление на ноль), если на главной диагонали встречается $0$.
*   **Частичный выбор (Pivoting):** Перед тем как исключать элементы ниже главной диагонали, алгоритм ищет максимальный по модулю элемент в текущем столбце и переставляет эту строку наверх. Это спасает программу от падений и значительно снижает накопление машинной погрешности округления.

#### 2. LU-разложение
Метод разложения матрицы $A$ в произведение нижней треугольной матрицы $L$ (где на главной диагонали стоят единицы) и верхней треугольной матрицы $U$:
$$A = L \cdot U$$
Решение любой СЛАУ после разложения сводится к двум тривиальным шагам:
1. Прямая подстановка: решаем систему $Ly = b$.
2. Обратная подстановка: решаем систему $Ux = y$.

**Выгода (Эксперимент 4.2):** Если требуется решить систему с одной и той же матрицей $A$, но $K$ разными векторами правых частей $b$, метод Гаусса будет каждый раз выполнять $O(N^3)$ операций. Метод LU-разложения позволяет вычислить $L$ и $U$ единожды за $O(N^3)$, а затем находить каждое новое решение за $O(N^2)$. Это снижает общую алгоритмическую сложность до $O(N^3 + K \cdot N^2)$, что дает кратный прирост производительности на больших системах.

#### 3. QR-разложение (Метод ортогонализации Грама-Шмидта)
Альтернативный метод разложения матрицы:
$$A = Q \cdot R$$
где $Q$ - ортогональная матрица (её особенность в том, что обратная матрица равна транспонированной: $Q^{-1} = Q^T$), а $R$ - верхняя треугольная матрица. Из-за свойств ортогональных матриц этот метод обладает феноменальной числительной устойчивостью и часто используется на практике для поиска собственных значений и решения задач методом наименьших квадратов. В реализации предусмотрена защита (проверка нормы вектора по порогу $\epsilon < 10^{-9}$) от линейно зависимых векторов-столбцов, при наличии которых разложение математически невозможно.

#### 4. Точность на плохо обусловленных матрицах (Эксперимент 4.3)
Матрица Гильберта задается формулой:
$$H_{i,j} = \frac{1}{i+j+1}$$

Она является эталонным примером *плохо обусловленной матрицы*. При малейшей погрешности машинного округления `double` результаты решения СЛАУ начинают катастрофически искажаться. С помощью генератора матрицы Гильберта и единичного вектора $x$ проводится эксперимент. Он вычисляет относительную норму невязки $\frac{||x_{calc} - x_{exact}||}{||x_{exact}||}$, наглядно доказывая, что с ростом размера матрицы $N \ge 10$ наивный метод Гаусса генерирует неадекватные ответы, тогда как метод с частичным выбором (Pivoting) или ортогональные разложения позволяют сохранить высокую точность.
